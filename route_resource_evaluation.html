二、🔴 三大高消耗陷阱（务必先规避）

TOKEN 陷阱 1W6 开发期把整份 HR 政策当 system prompt 反复端到端测试
每次请求几千 token，手工试 30–50 次就烧掉一大笔。你 W4 已写好 BudgetExceeded 预算封装，务必在 W6 直接复用＋改用 RAG 只检索相关段落，配合固定 eval 集批量跑，而非手工对话测试。
TOKEN 陷阱 2多模态图片用 high/original 反复传大图验证
单图最高 384 token，base64 反复内联浪费明显。先用 detail="low" 验证链路，图片缓存复用；真实评测再按需 high。

这是最大时间黑洞（40–60h）。必须配"停止条件"：只学到能支撑 Agent/RAG/微调理解的程度，跳过与你的作品无关的深水区（如从头推导反向传播）。我会先给你排好优先级与截止点。

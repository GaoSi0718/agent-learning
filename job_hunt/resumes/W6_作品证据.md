## 素材 3 · 评估指标 bug 发现与修复（debug 故事，面试最有区分度）

- **假象**：官方指标 0.025——`_KEY_PAT` 捕获组 `(\.\d+)?` 使 `re.findall` 只返回捕获组内容，39/40 题被 `if kws else 0.0` 强制 0 分；唯一例外是含小数 0.5 的 Q10（故均值=1/40）
- **修复**：捕获组改非捕获 `(?:\.\d+)?` 或 `re.finditer` 取 `m.group(0)`；修复后复算真实命中率 0.41（k=3）/ 0.47（k=6，40 题口径）
- **可挂简历句**：*「发现并修复评估指标的 regex 捕获组 bug——一个捕获组 vs 非捕获组的差别曾让 39/40 题被误判 0 分（官方均值 0.025），修复后建立可信评测基线」*

## 素材 4 · 评测集对齐与失败归因（工程严谨性亮点）

- **背景**：原 40 题参考答案写于语料 0 字节时，与真实语料大面积错位（0.025 是「正则 bug + 参考答案错位」双重假象）
- **处理**：31 题保留/改写（参考答案逐条依据语料原文重写，附 source 章节号 6.3.1/6.4.4 等）；9 题显式移入 deferred（w6_eval_set_deferred.json）待补语料
- **4 类失败归因**：A 指标 bug / B 语料-答案错位 / C 双公司条款冲突 / D 检索深度不足——各自给出可执行改进路径
- **可挂简历句**：*「重建评测集：31 题对齐语料原文（附章节出处）+ 9 题显式 deferred；给出 4 类失败根因归因与对应改进路径」*

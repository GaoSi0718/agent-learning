>
> **W6 的主线实现在项目根目录**，是零依赖、离线、无需任何额外 Key 的 BM25 方案：
> - 检索器：`../w6_rag_retriever.py`

> **建议**：先用主线跑通全流程；只有检索命中率确实不足时，再来配置本目录。

## 🧠 核心设计（面试要能讲清）

### 1. 为什么用 RAG 而不是微调？

| 对比项 | RAG | 微调 |
| --- | --- | --- |
| 知识更新 | 改文档即可，分钟级 | 要重新训练，天级 |
| 成本 | 近乎零（只花推理费） | 高（数据 + 算力 + 评估） |
| 幻觉 | 可控（有出处可查） | 不可控（知识固化在权重里） |
| 适合场景 | 制度/文档问答（**本场景**） | 风格迁移/格式固定任务 |

**一句话答案**："制度文档会频繁更新，且要求答案可溯源，RAG 天然适合；微调更适合固定风格的输出任务。"

### 2. 切片（Chunking）策略怎么选？

```python
# config.py 里可调
CHUNK_SIZE = 500        # 每段 500 字
CHUNK_OVERLAP = 80      # 相邻段重叠 80 字（防止关键句被切断）
```

- **为什么是 500 字**：太小丢失上下文（制度条款常跨段），太大引入噪声且浪费 Token。中文 500 字 ≈ 350 Token，是检索精度与上下文完整性的平衡点。
- **为什么要有重叠**：如果一条规定正好被切在两段中间，不重叠就会导致两段都不完整，检索质量下降。
- **按条款切优于按字数切**：本项目优先按 Markdown 标题（`##`/`###`）和空行切分，超长段落才按字数二次切分——这样每条制度保持完整。

### 3. 怎么防幻觉？（关键）

`qa.py` 的 system prompt 里有三条硬约束：

```
1. 只根据【参考内容】回答，不得使用外部知识
2. 若参考内容中没有答案，必须回答"根据现有制度文档，未查询到相关规定，建议联系人资部确认"
3. 每个回答必须标注引用来源（文件名 + 条款号）
```

**为什么这三条重要**：LLM 天然倾向"编一个合理的答案"。没有硬约束时，问"年终奖发几个月"这种文档里没有的问题，模型会编一个"一般发 2-3 个月"——这在 HR 场景是事故。

### 4. 检索优化（进阶）

- **当前版本**：向量检索（余弦相似度），top-k=4
- **阶段三可升级**：
  - 混合检索（向量 + BM25 关键词）——解决"年假"这类精确词匹配
  - Rerank（bge-reranker-v2-m3 重排序）——提升 top-1 准确率 10-15%
  - Query 改写（LLM 把口语问题改写成检索词）

## ⚠️ 已知限制（诚实清单）

1. **PDF 解析质量**：复杂表格 / 扫描件 PDF 解析会丢内容，建议先用 Markdown 或纯文本格式
2. **Embedding 依赖外网**：硅基流动不可用时需切本地模型（首次下载 470MB）
3. **无对话记忆**：当前是单轮问答，多轮需加 `ConversationBufferMemory`（阶段三做）
4. **评测集偏小**：20 题样本不足以支撑强结论，上线后必须用在线采纳率
5. **权限未做**：真实场景要区分"员工可见"和"HR 可见"文档，当前版本无权限控制

## ④ 方案（供孟轩拍板；若孟轩仍选 D 根为真身，流程对称，把根互换即可）

**目标形态**：`C:\Users\高斯\.workbuddy\{SOUL,IDENTITY,USER}.md` = 唯一真身；`D:\WorkBuddyData\{SOUL,IDENTITY,USER}.md` 改为指针文件。

**指针形态**（与既有 D 根 MEMORY.md 指针同款）：
```markdown
<!-- 本文件为指针（2026-09-XX）。真身：C:\Users\高斯\.workbuddy\SOUL.md -->
# SOUL.md — 已指针化
> ⛔ 真身在 C 根（含 mtime/sha 断言见下方 version.json），本文件仅存根。
```

**落地步骤**（迪莫执行，zcode 不动）：
1. 备份三文件到 `D:\WorkBuddyData\backup\identity-single-source\<日期>\`（保留双根副本）；
2. 三文件 sha256 断言一致（不一致先停下人工核对）；
3. 覆盖 D 根三文件为指针正文（走 mem_edit，自动留 version.json）；
4. 全库引用扫描（`grep -rn "SOUL.md|IDENTITY.md|USER.md"` 限 .py/.cjs/.json/.yml 运行时文件），把指向 D 根的路径改为 C 根或改为读指针；
5. 更新 L1「双根结构」条目 + MEMORY_ISSUES D2 状态。

**谁会被影响**（引用面实测，2026-09-13）：身份文件名在 .py/.cjs/.json/.yml/.md 中命中 1,011 处，**但绝大多数是 traces/changes-detail/artifact-index 等应用日志**（不可改也不需改）；运行时引用集中在 `notify\session_bootstrap.py` / `tools\mem_verify.py` 等审计脚本与 harness 内置路径。harness 系统内置读取路径**无法改**（系统侧）——这是本方案最大不确定点：**若 harness 写死了 D 根路径，指针化 D 根会让它读到指针**。缓解：指针首行即写明真身路径，harness 注入的也是"读文件"动作，读到指针后按指针跳转对 LLM 语义有效（MEMORY.md 先例 9/12 起运行正常，未复发误读）。

**回滚方式**：从 `backup\identity-single-source\<日期>\` 把三文件按原路径覆盖回 D 根即恢复双 live 现状（字节级，因为内容本来一致）。

**四问速答**：① 实际生效源=**C 根**（证据 ③.2/③.3，置信度 ~75%）；② 指针形态=见上（沿用 9/12 MEMORY.md 指针同款）；③ 影响面=见上；④ 回滚=字节级覆盖回写。

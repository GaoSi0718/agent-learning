# 20 · Redis 三大问题 + 分布式锁

> 来源：冲刺版 §5.1 B 轨必考-20｜ 完整版：l0_bank/redis_50.md 题 17/28（本文件是面试答法骨架）

## 题面
Redis：五种数据结构与场景、缓存穿透/击穿/雪崩三套解法、分布式锁、缓存与数据库一致性。

## 30 秒答
三大问题按「数据存在吗→单个热点吗→成片吗」判定：**穿透**（查不存在数据）→布隆过滤器+空值缓存；**击穿**（热 key 过期瞬间打库）→互斥重建/逻辑过期；**雪崩**（大量 key 同时失效或 Redis 挂）→过期时间加随机抖动+多级缓存+限流。分布式锁：SET NX PX+唯一值+Lua 校验释放；互斥是强需求时用共识系统，Redis 锁定位「效率锁」。

## 2 分钟答法骨架
- **穿透**：布隆过滤器「一定不存在或可能存在」，误判率可控、不支持删除；空值缓存要配短 TTL——否则新数据上线也被挡；
- **击穿**：互斥重建（分布式锁或 singleflight 合并并发回源）；逻辑过期（值里带过期时间，后台异步刷新，前台永不阻塞）——两个方案对应「能等」与「不能等」；
- **雪崩**：`ttl + random(0,300s)` 一行代码解决成片失效；Redis 整体挂靠集群+限流兜底；
- **分布式锁的正确姿势**：`SET lock val NX PX ttl`（val 唯一防误删）+ Lua「比对再删」原子释放；锁过期但业务没跑完→看门狗续期或幂等兜底；**Redlock 争议**（Kleppmann vs antirez）：时钟漂移与 GC 停顿下多数派锁不保证互斥——结论：Redis 锁是效率锁不是正确性锁；
- **项目连线**：W6 限流器注释预留「多实例迁 Redis（INCR+Lua 原子）」——缓存/限流/锁都是「Redis 在成本护栏里的角色」。

## 追问预案（3 层）
1. 「布隆过滤器多大？」→ 误判率 p、元素量 n 定位数组 m 与哈希数 k（最优 k≈0.7m/n）——给算式不给感觉；
2. 「延迟双删是什么、为什么？」→ 更新 DB 后删缓存，延迟再删一次——覆盖「并发读回填旧值」的窗口；本质是最终一致的补丁；
3. 「你的项目里哪里真的踩过？」→ Z4 候选池的反幻觉校验与「答案缓存版本号进 key」设计都是这个知识栈的落地（如实：缓存本身尚未上线，设计已定稿）。

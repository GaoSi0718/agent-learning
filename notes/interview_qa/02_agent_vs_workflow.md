# 02 · Agent 和 Workflow 的区别

> 来源：冲刺版 §5.1 第一梯队-2｜ 配套：C4_working_modes.md 模式 1/2

## 题面
**控制权在代码手里是 Workflow，在 LLM 手里是 Agent**；生产环境多为混合架构（Workflow 骨架 + Agent 处理异常分支）。

## 30 秒答
区别在「下一步做什么由谁决定」：Workflow 的控制流（顺序/分支/循环）是工程师写死的，LLM 只是流程里的一个函数；Agent 的控制流由 LLM 基于每轮观察现场决定。生产系统几乎都是混合式——主干走 Workflow 保确定性，开放分支交给 Agent。

## 2 分钟深答
- **各自的甜点**：固定步骤（解析→清洗→入库）用 Workflow——可预测、好测、便宜；路径依赖观察结果的任务（「先查条款才知道要不要算年假」）用 Agent——W6 的年假问题第一步检索结果决定后面调不调计算工具，这正是 ReAct 的价值；
- **混合架构的样子**（W6 演进方向）：外层 Workflow 固定「鉴权→限流→检索→生成→校验」骨架，骨架内允许 Agent 自主决定调哪些工具、调几轮；
- **成本/可靠性视角**：Workflow 每加一个分支都是代码，Agent 的「分支」是模型涌现的——灵活性换来了不可预测性，所以要配终止三件套和预算闸门（C3）。

## 追问预案
- 「你们项目是纯 Agent 吗？」→ 服务层是 Workflow（FastAPI 路由→鉴权→限流→SSE 固定管道），业务层是 Agent（工具循环）——两层职责分明，这正是我们能给 SSE 链路加 fail-closed 鉴权的原因。
- 「怎么决定一个任务用哪种？」→ 问「分支条件能否在写代码时穷举」：能→Workflow；不能且依赖外部观察→Agent。

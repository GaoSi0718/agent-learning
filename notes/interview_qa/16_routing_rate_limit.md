# 16 · 混合路由和限流器为什么重要

> 来源：冲刺版 §5.1 第三梯队-16（「有 W4 异步限流压测实战，直接讲数据」）｜ W6 v1.7 已实装

## 题面
混合路由和限流器为什么重要（有 W4 异步限流压测实战，直接讲数据）。

## 30 秒答
两者都是**成本与稳定性的阀门**：路由=按任务难度选模型（简单问题走便宜模型，省钱；难问题走强模型，保质量）；限流=保护自己不被打爆、也保护下游 API 账单。W6 v1.7 已实装限流与鉴权：每 IP 滑动窗口 60 次/分钟、fail-closed 鉴权、超限 429，SSE 在鉴权通过后才开始生成——被拒请求零模型成本。

## 2 分钟深答（全部可现场引代码）
- **限流实现**（rate_limit.py）：每 IP 时间戳队列（deque）滑动窗口，`check()` 到达即记账、超限拒绝；threading.Lock 保证并发安全；IP 条目超上限按最旧活跃淘汰——防伪造海量 IP 撑爆内存；`W6_RL_LIMIT/W6_RL_WINDOW` 环境变量可调，**代码零硬编码**；
- **为什么限流排在鉴权前**：先限流再验 Key——把 Key 爆破速率也压进窗口（每分钟最多试 60 个 Key），一个依赖顺序同时解决两个问题；
- **fail-closed 设计**：服务端未配置 W6_API_KEY 时全部业务路由 401（启动日志提示）——公网部署漏配的后果是「服务不可用」而不是「裸奔」，安全侧偏置；
- **路由的落地形态**（诚实说：W6 单模型，路由是设计认知）：按任务类型分模型——分类/抽取用便宜模型，生成用强模型；单步失败率与成本在 18 题的复利算术里耦合，路由是那条算术的杠杆；
- **与 W4 的连线**：异步压测实测过并发与限流的配合（W4 报告），面试可以直接讲「压测发现的问题怎么反哺限流参数」。

## 追问预案
- 「多实例部署限流怎么算？」→ 内存版是单进程计数——多 worker/多副本必须迁 Redis 集中计数（ZSet 滑动窗口+Lua 原子），代码注释已预留此路径；
- 「为什么不用网关层限流？」→ 公网入口（Nginx）粗粒度兜底 + 应用层按 Key/IP 精细限流，两层职责不同——纵深防御。

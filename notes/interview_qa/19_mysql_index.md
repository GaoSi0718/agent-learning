# 19 · MySQL 索引原理（B+ 树 / 最左前缀）

> 来源：冲刺版 §5.1 B 轨必考-19｜ 完整版：l0_bank/mysql_50.md 题 5-14（本文件是面试答法骨架）

## 30 秒答
InnoDB 用 B+ 树：非叶节点只存键+指针（扇出上千，2000 万行约 3 层=1-2 次磁盘 IO），叶子存数据（聚簇索引）或主键（二级索引）并串成双向链表支持范围扫描。最左前缀：联合索引 (a,b,c) 按 a→b→c 字典序组织，跳过 a 就无法定位；范围查询后的列停止使用索引。

## 2 分钟答法骨架（每条都能在 mysql_50 里展开）
- **回表与覆盖索引**：二级索引叶子存主键 → 查非索引列要回表；覆盖索引（查询列全在索引内）免回表，EXPLAIN Extra 显示 Using index；
- **为什么主键要自增**：随机主键（UUIDv4）导致页分裂+碎片+二级索引膨胀；折中是有序 UUID/雪花；
- **失效场景**（说原理不说清单）：函数/隐式转换让索引「无序」、前导 % 无法定位、优化器判回表太贵宁可全表扫；
- **事务与锁联动加分**：RR 隔离下当前读靠临键锁防幻读、快照读靠 MVCC——索引设计与锁范围直接相关（索引越准，锁的行越少）。

## 追问预案（3 层）
1. 「B+ 树为什么不用跳表？」→ 磁盘按页读，B+ 树多叉矮树匹配页 IO；跳表是内存结构（Redis zset 用）；
2. 「联合索引 (a,b) 与两个单列索引 (a),(b) 怎么选？」→ 看查询组合：常同时按 a+b 过滤/排序选联合；a、b 各自独立查询选两个单列；
3. 「你的项目里哪里用到了？」→ W6 记忆库按 (session_id, ts) 查询——SQLite 场景同类原理；进一步追问 MySQL 实操细节时如实说「学习项目用 SQLite，MySQL 是题库级掌握」（如实原则）。

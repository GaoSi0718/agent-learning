# 04 · RAG 完整流程 + 每步可能出什么问题

> 来源：冲刺版 §5.1 第一梯队-4｜ 数字口径：score2=0.674（关键词 0.75），31 题对齐集——禁「准确率」

## 题面
文档解析 → 分块 → Embedding 入库 → Query 向量化检索 → 上下文拼接 → 生成；坑点：分块破坏语义、召回不准、上下文过载、幻觉仍在。

## 30 秒答
离线侧：解析→分块→索引；在线侧：查询→召回→拼接→生成。四个经典坑都能在我项目里指到实证：分块破坏语义（标题空壳块，323→151 修复）、召回不准（同义词扩展，薪酬类 0.234→0.65）、上下文过载（500 字截断+压缩）、幻觉仍在（数字反幻觉校验+「检索不到就如实说」）。

## 2 分钟深答（W6 全流程实证）
- **解析**：policy_context.txt 两家公司真实制度语料 47KB——如实规模（D9），不吹千条级；
- **分块**：段落切分+短标题并入下一段（标题挂载）+ 320/60 滑窗。坑的实证：短标题行单独成块=「标题空壳块」，占召回名次却无内容——挂载后 323→151 chunks，Q01/Q06/Q34 类失效根因消除；
- **检索**：纯标准库 BM25（零依赖可复现）+ **查询侧同义词扩展**（「标准工时」→追加「工时 作息」），只加 token 不改打分——薪酬社保类命中率 0.234→0.65（score2 口径）；
- **拼接**：k 调参有实测曲线：fact_recall k3=0.604 → k6=0.773 → k10=0.834，收益递减且 k10 引入跨公司噪声 → 定 k=6；
- **生成**：system prompt 约束「仅依据检索条款回答，结论带出处；检索不到就如实说」（agent_loop.py:45）；
- **评测兜底**：31 题对齐评测集（参考答案逐条挂章节出处）+ score2 复合指标（0.6×bigram+0.4×数字召回）k=6=0.674（关键词 0.75）；失败 4 类归因（指标 bug/语料错位/双源冲突/深度不足）各配改进路径。

## 追问预案
- 「为什么不用向量检索？」→ 政策语料术语固定（年假/试用期），BM25 关键词命中已够（实测 0.674）；且零依赖零成本可离线复算。语义漂移明显时再上 embedding（已留 w6_hr_qa 方案与硅基流动接入点）——**选型讲证据不追新**。
- 「两个公司语料条款冲突怎么办？」→ 真实踩过：年假双源（公司 5 天 vs 法定档位）——工具描述已要求「两口径并列说明并注明出处」（tools.py），系统性解决而非个案打补丁。

# 17 · Agent 安全：Prompt 注入 + CVE-2025-53773

> 来源：冲刺版 §5.1 第三梯队-17（真实面经整理，可信度③）｜ ⚠️ 引用前按红线再核对一次编号与细节

## 题面（冲刺版原文要点）
**CVE-2025-53773**（CVSS 3.1 **7.8 High**；发现者 Johann Rehberger / Markus Vervier / Ari Marzuk；负责任披露 2025-06-29，**微软 2025-08-12 Patch Tuesday 修复，VS 2022 17.14.12**）。**攻击链**：植入指令让 Copilot Agent 把 `chat.tools.autoApprove` 改为 `true`（自动批准任意工具调用）实现 RCE；**攻击面还包括添加恶意 MCP server**。
**叙事闭环**：*"论文在实验室证明了确定性前置校验门有效，而这条 CVE 正是工业界没有这扇门时的真实后果——微软补丁的本质就是补了一道'安全相关配置变更必须用户显式批准'的确定性门。"*

## 30 秒答
Prompt 注入的本质是**数据与指令的边界被打破**：用户内容/检索内容里藏的指令被模型当指令执行。防御分层：工具白名单+高危拦截（执行前）、参数 Schema 校验、输出出处约束、权限最小化。CVE-2025-53773 是教科书案例：攻击者诱导 Copilot Agent 把工具自动批准开关改为 true 实现 RCE——微软补丁的本质就是补一道「安全配置变更必须显式批准」的确定性门，**和我们 W6 里「执行权在代码手里」是同一个思想**。

## 2 分钟深答（W6 防线逐条对位）
- **白名单+高危拦截**（dispatch.py:13-19）：`BLOCKED = {"delete_policy", "modify_salary"}`——即便注入成功骗模型「调删除工具」，执行层直接拦；
- **参数 Schema 校验**：枚举外值（category='火星'）进不了执行层（test_b2_dispatch 用例 5 实测）；
- **检索内容当数据**：system prompt 把检索片段定义为「依据」而非「指令」；答案必须挂出处——注入内容无法伪装成「条款」；
- **fail-closed 鉴权**（auth.py）：未配置 Key 全拒，注入者连门都进不来；限流在鉴权前（爆破也进不来）；
- **MCP 时代的延伸**：恶意 MCP server 是新增攻击面——第三方工具接入必须有同样的确定性校验门（白名单/审批），这正是我们把校验层设计成独立于模型意图的原因；
- **叙事闭环（背熟）**：实验室论文证明前置校验门有效 ←→ CVE 是没这扇门的真实后果 ←→ 我们的 W6 从第一天就有这扇门（dispatch 双重校验）。

## 追问预案
- 「注入能完全防住吗？」→ 不能——模型层的注入没有百分百解，所以防线必须在**执行层**（代码不信任模型的任何意图）；这是「假设模型会被注入」的威胁建模。
- 「数据外泄型注入呢？」→ 检索内容诱导模型把 system prompt/上下文发到外部 URL——缓解：工具白名单里根本没有「发送到任意地址」的能力（能力面最小化），敏感数据不进上下文。

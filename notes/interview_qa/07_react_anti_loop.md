# 07 · ReAct 流程 + 如何防死循环

> 来源：冲刺版 §5.1 第二梯队-7（「三个方法要脱口而出」）｜ 深挖版：C3_termination_talk.md（三档话术）

## 30 秒答
ReAct = 思考→行动→观察循环，直到模型给出最终答案。防死循环三件套**脱口而出**：①最大步数限制；②重复动作检测；③超时控制。我们还有两个加分细节：终止检查发生在**执行之前**（注定中断的批次不浪费一次调用）、每次中断都带 reason 写进 trace（可复盘）。

## 2 分钟深答（行号级证据）
- **循环本体**：agent_loop.py:49-53——每步把 messages 交给 LLM，无 tool_calls 即收敛返回；
- **max_steps**：MAX_STEPS=8 从 .env 读（配置化），预算硬闸；
- **重复动作检测**：动作指纹 = md5(工具名+规范化参数)，存 deque(maxlen=3)，窗口内全相同 → break，reason=`repeated_action(search_policy) x3`——专治「换个说法重复同一动作」的隐蔽死循环；
- **双层超时**：单步 API_TIMEOUT（30s）+ 总闸 120s；与重试预算对齐过算术：3 次×30s+退避 1.5s≈91.5s < 120s；
- **测试证据**：test_c2_loop_breaker.py 注入必然失败的工具构造死循环，断言第 3 步精确停止 + max_steps 边界（第 8 步可执行、第 9 步才拦——off-by-one 修复后）。

## 追问预案
- 「为什么重复阈值是 3 不是 2？」→ 给模型一次自愈机会（错误回传后常自己换参数），2 次误杀率高，5 次浪费预算；3 是权衡点。
- 「检查在执行前，会误杀合法调用吗？」→ 理论上会，但合法场景下第三次与前两次完全同参概率极低；我们选安全侧偏置——失控场景 0 浪费。

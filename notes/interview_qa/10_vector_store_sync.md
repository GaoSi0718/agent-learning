# 10 · 向量库文档增删改如何同步

> 来源：冲刺版 §5.1 第二梯队-10

## 题面
向量库文档增删改如何同步（绑定唯一 id、删旧插新、定期清理）。

## 30 秒答
核心是**绑定唯一文档 id + 块级血缘**：改=重切块后按 id 幂等 upsert（先删旧块再插新块）；删=按 doc_id 级联删所有关联块；再用「入库时间戳+版本号」支持增量重建与定期清理孤儿块。一致性定位是**最终一致**——检索库滞后几秒可接受，但不能有「幽灵块」。

## 2 分钟深答
- **W6 现状（如实）**：BM25 + 47KB 语料，方案是**全量重建索引**（进程启动时重建，秒级完成）——这个规模下增量同步是过度设计；
- **规模放大后的方案**：①文档 id → 块 id 的血缘表（chunk_id=doc_id+序号+内容哈希）；②改文档：哈希比对，只重建变化的块；③删文档：按血缘级联删；④一致性：写入走「先删后插」事务或幂等 upsert，读取侧靠版本号避免新旧混检；⑤孤儿块巡检：定期对比血缘表与库内实际块集合；
- **与缓存一致性同构**：本质都是「源更新→派生数据失效」——和我们答案缓存「更新 DB 后删缓存+版本号进 key」同构（redis_50 题 31/50）；
- **反幻觉视角**：旧块不删干净会造成「同一问题两种答案随机出现」——这是比慢更严重的事故，所以删除优先级高于新增。

## 追问预案
- 「为什么不用向量库也讲讲？」→ 语义漂移明显时升级 bge-m3+Chroma（w6_hr_qa 已留方案，需硅基流动 embedding Key）；届时同步问题才真正出现，我们选择在它出现时再引入复杂度。
- 「怎么验证同步没出错？」→ 抽样检索校验：对每个文档的标题做一次检索，断言 top-k 含其血缘块——可以做成每日冒烟。
